## Goal
Every pull request automatically runs the same checks that agents run by hand,
and GitHub shows the result on the PR before the owner approves it.

## Context
[ADR-0011](../docs/decisions/0011-pull-request-workflow.md): every change reaches
`main` through an owner-approved PR. Coordinator review runs the checks
locally, but an automatic check is a safer, visible gate. This was proposed as
a follow-up by T-002 and T-003.

## Scope
**In:**
- `.github/workflows/ci.yml` (GitHub Actions), triggered on pull requests to
  `main` and on pushes to `main`. It runs on `ubuntu-latest`, and on
  `windows-latest` if that is cheap enough (justify the choice in the Log). It
  uses uv with caching and runs:
  - `uv sync --locked`
  - `uv run pytest`
  - `uv run ruff check .`
  - `uv run ruff format --check .`
  - `uv run sondaje validate`
  - `uv run sondaje validate --against origin/main`, on pull requests only
    (registries must stay append-only); fetch enough git history for it.
- A status badge in `README.md` (shared file allowed for this line only).

**Out:**
- Branch protection settings. The owner configures them; propose the exact
  required check name under Follow-ups.

## Acceptance criteria
- [x] The workflow passes on the task's own PR.
- [x] A deliberately broken commit (pushed to a throw-away branch and PR, then
      closed) makes the workflow fail. Record the run links in the Log.
- [x] The run takes a reasonable time (record the duration).

## Follow-ups
- **Branch protection (owner):** on `main`, require the status check
  **`Required checks`** (job `required` of workflow `CI`; the PR checks list
  shows it as `CI / Required checks (pull_request)`). It is green only when
  every matrix job (`Checks (ubuntu-latest)`, `Checks (windows-latest)`)
  succeeded, so the protection rule does not need to change if the matrix
  changes. Also tick "Require branches to be up to date before merging" if
  the owner wants `validate --against origin/main` to always run against the
  latest `main`.
- ADR-0011 "Recommended GitHub settings" and AGENTS.md §4 "Review and merge"
  could mention that a PR is merged only with a green `Required checks`
  (shared files; not edited here).
- Action versions are pinned by commit SHA (`actions/checkout` v7.0.1,
  `astral-sh/setup-uv` v10.4.0). A `.github/dependabot.yml` with the
  `github-actions` ecosystem would keep them current.
- CI pins uv `0.12.21` (the team's version). Consider declaring it once in
  `pyproject.toml` (`[tool.uv] required-version`) so local and CI cannot
  drift; then the workflow's `version:` line can be dropped.

## Outcome
`.github/workflows/ci.yml` (workflow `CI`) runs on pull requests to `main` and
pushes to `main`: a `Checks (<os>)` matrix job on Ubuntu and Windows runs
`uv sync --locked`, `uv run pytest`, `uv run ruff check .`,
`uv run ruff format --check .`, `uv run sondaje validate`, and, on pull
requests, `uv run sondaje validate --against origin/main`; a `Required checks`
job aggregates the matrix into one status check for branch protection. uv is
set up with `astral-sh/setup-uv` (pinned SHA, package and Python caching).
`README.md` has a CI badge. A run takes ~45–50 s. Key commits: cdcab09
(workflow + badge), aaf5d27 (uv-managed Python on every OS).
Known limitations: branch protection is not configured (owner, see
Follow-ups); the validator's 88 warnings are printed in every run but do not
fail it (no `--strict`).
